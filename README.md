# VCE Read Aloud 🔊

A local, private text-to-speech app for reading student essays aloud — built
for proofing class sets and for students who benefit from audio support.

- **Runs entirely on your Windows laptop.** Essays never leave your machine
  unless you explicitly switch to the optional cloud voice.
- **One click to start.** Double-click `start.bat`; your browser opens the app.
- **Zero configuration.** Works immediately with the voices already installed
  with Windows.

---

## Getting started (Windows)

1. **Install Python** (once): get Python 3.10 or newer from
   [python.org/downloads](https://www.python.org/downloads/) and tick
   **“Add python.exe to PATH”** during installation.
2. **Double-click `start.bat`.**
   The first run creates a private environment and installs dependencies
   (needs internet once, takes a minute or two). Every run after that starts
   in seconds and works offline.
3. Your browser opens at `http://127.0.0.1:8471` — that address is only
   reachable from your own laptop.

> Tip: right-click `start.bat` → *Send to* → *Desktop (create shortcut)*,
> then rename the shortcut “Read Aloud”. One double-click each morning.

To stop the app, close the black console window (or press `Ctrl+C` in it).

## Daily use

- **Add essays** — press `N`. Pick (or type) the class and student, then
  either paste text or import `.docx` / `.pdf` / `.txt` files. You can drop
  a whole handful of files at once; each becomes its own essay.
- **Listen** — press `Space`. Click any word to start reading from there.
  The current word is highlighted as it's spoken.
- **Navigate** — `J`/`K` (or `↓`/`↑`) jump between paragraphs; `←`/`→` skip
  5 seconds; `PgUp`/`PgDn` move between essays in the list.
- **Export audio** — press `E` for an MP3 of the current essay, or
  **Batch export** (`B`) to generate MP3s for every essay in the selected
  class in one action. Files are also kept in `data/audio/`, named
  `Class--Student--Title--id.mp3`.
- **Fix pronunciations** — *Pronunciation fixes* (bottom-left). If a voice
  mangles “Keneally”, tell it to say “Kuh-nee-lee”. Fixes apply to the audio
  for all essays and never change the text on screen.
- **Voice & speed** — press `,` for Settings: choose a voice, preview it,
  and adjust speed, pitch and volume with sliders.

Press `?` inside the app for the full keyboard shortcut list — the app is
designed so almost everything is one keystroke, with large click targets
where clicking is unavoidable.

## Where your data lives (privacy notes)

Everything is stored in the `data/` folder next to the app:

| What | Where |
|---|---|
| Essays, classes, students, pronunciation fixes | `data/library.db` (SQLite database) |
| Generated audio files | `data/audio/` |
| Settings, including any cloud API key | `data/settings.json` |

- Nothing is uploaded anywhere. The app listens only on `127.0.0.1`
  (your own machine) — other devices on the school network cannot reach it.
- With the default **Windows voices** engine, speech is generated by
  Windows itself, entirely offline.
- If you choose the optional **Azure** engine, essay text is sent to
  Microsoft's speech service to generate the audio — the app warns you about
  this in Settings, and you can switch back at any time.
- Back up = copy the `data/` folder. Delete everything = delete the `data/`
  folder. The `data/` folder is excluded from git, so student work and your
  API key can never be accidentally committed or pushed.

## Optional upgrade: more natural cloud voices (Azure AI Speech)

The built-in Windows voices are free, private and instant. If you want
noticeably more natural voices (including Australian English “Natasha” and
“William”), you can plug in a Microsoft Azure AI Speech key:

1. Create a free Azure account at [azure.microsoft.com](https://azure.microsoft.com/free/).
   The free tier includes 500,000 characters of neural speech per month —
   plenty for a class set of essays.
2. In the Azure portal, create a **Speech service** resource (choose the
   region `australiaeast`).
3. On the resource's **Keys and Endpoint** page, copy **Key 1** and the
   **Region** name.
4. Install the Azure SDK into the app's environment (once):
   open a console in this folder and run
   `.venv\Scripts\pip install -r requirements-azure.txt`
5. In the app, open Settings (`,`) → engine **Azure AI Speech** → paste the
   key and region → **Save settings** → **Preview voice**.

The key is stored only in `data/settings.json` on your laptop. It is never
hardcoded, never committed to git (the whole `data/` folder is ignored),
and the app never displays it back once saved.

Word-level highlighting works with both engines: Windows SAPI and Azure both
report word boundary timings, which the app records alongside the audio.

## Running the tests

```
python tests/test_pronunciation.py
python tests/test_smoke.py
```

On non-Windows machines the app falls back to a development voice
(silent placeholder, or eSpeak if installed) so the full pipeline can be
tested anywhere; real voices come from Windows SAPI or Azure.

## Project layout

```
start.bat            one-click Windows launcher (creates .venv on first run)
run.py               starts the local server and opens your browser
app/                 FastAPI backend
  main.py            API routes
  db.py              SQLite storage (classes, students, essays, rules)
  text_extract.py    .docx / .pdf / .txt text extraction
  pronunciation.py   substitution rules + offset mapping for highlighting
  synth_service.py   synthesis orchestration, caching, paragraph offsets
  audio_convert.py   WAV -> MP3 (lameenc, no ffmpeg needed)
  tts/               speech engines: Windows SAPI5, Azure, dev fallback
static/              the web UI (no build step, plain HTML/CSS/JS)
tests/               smoke + unit tests
data/                YOUR content (created on first run; never in git)
```
